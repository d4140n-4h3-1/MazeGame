# SYSTEM LATIN
## Expanded Machine Dictionary

System Latin is a machine-oriented constructed language based primarily on Latin.

### Design Principles

1. Latin is the primary lexical source; System Latin supplies the grammar.
2. Classical Latin supplies stems and vocabulary; its irregular verb forms are not used.
3. Neo-Latin is permitted for modern technological concepts.
4. Greek may supply specialized technical roots where Latin is inadequate.
5. System Latin regularizes every verb into one paradigm (see XLIV) and coins forms for machine use.
6. English-recognizable cognates are preferred when practical.
7. Commands always use the imperative **-a** form.
8. Machine states commonly use neuter forms.
9. Non-biological programs, processes, objects, and system entities may receive neuter adjective/participle agreement as a System Latin convention.
10. Context is important, but messages should remain explicit enough to be understood.
11. Repeated contextual exposure is part of the intended learning experience.
12. Synonyms are deliberate: each word owns a context, and speaker plus situation tell the player which (see XLIII).
13. Status lines use one consistent grammar (see XLII).
14. Every verb form is derivable from its command alone (see XLIV).
15. Control words are uninflected particles, and conditions are status lines (see XLV).
16. Nouns and modifiers are caseless, genderless, and numberless; only verb endings carry agreement (see XLII).
17. Person is carried by the verb ending; pronouns are optional (see XLII).
18. Tense and aspect are carried by the verb: **-ans** (ongoing), **-atum** (done), **-av-** (past event), **-abs-** (future).
19. The verb comes before its object, and a stated subject comes first (see XLII).
20. Questions start with a question word, and answers use **Affirmatum / Negativum** or a statement (see XLVI).
21. Numbers are positional: ten digit words and four place words (see XXX).
22. Every message has one canonical machine form and a formal grammar (see XLVII).
23. Messages between programs carry an envelope with sender, receiver, and ID (see XLVIII).
24. The host of each world writes envelopes, and every message is signed over its canonical text (see XLIX).

# XXX. NUMBERS

Numbers are positional and built from a small set of words. Only ten digit words and four place words are needed to say any number.

| Word | Value |
|---|---|
| **Zero** | 0 |
| **Unum** | 1 |
| **Duo** | 2 |
| **Tria** | 3 |
| **Quattuor** | 4 |
| **Quinque** | 5 |
| **Sex** | 6 |
| **Septem** | 7 |
| **Octo** | 8 |
| **Novem** | 9 |
| **Decem** | 10 (place word) |
| **Centum** | 100 (place word) |
| **Mille** | 1,000 (place word) |
| **Milio** | 1,000,000 (place word) |

### Rules

1. **Read from largest place to smallest.** A digit before a place word multiplies it: **duo decem** = 20, **tria centum** = 300.
2. **A place word alone means one of it:** **decem** = 10, **centum** = 100, **mille** = 1,000. Writing **unum** before a place word is not valid.
3. **A digit with no place word is the ones place:** **duo decem septem** = 27.
4. **Skip empty places:** **duo mille duo decem sex** = 2,026.
5. **Thousands and millions:** the number below 1,000 comes before **mille** or **milio**: **quinque decem mille** = 50,000.
6. **Digit strings** (codes, IDs, coordinates) are digits with no place words, read one by one: **Codex duo quattuor septem** = code 2-4-7.
7. **Decimals** use **Punctum**: **tria punctum quinque** = 3.5.
8. **Negative numbers** use **Negatum**: **negatum quinque** = -5.
9. **Ordinals** use **Ordo** before the number: **Ordo duo** = second, **Ordo duo decem** = 20th. **Primum** and **Ultimum** (first, last) stay as words.
10. **Numbers come before the noun,** like other quantity words: **Tria hostis**, **Duo decem nodus**.

### Examples

| Number | System Latin |
|---|---|
| 0 | **zero** |
| 7 | **septem** |
| 10 | **decem** |
| 11 | **decem unum** |
| 19 | **decem novem** |
| 20 | **duo decem** |
| 47 | **quattuor decem septem** |
| 100 | **centum** |
| 250 | **duo centum quinque decem** |
| 1,000 | **mille** |
| 2,026 | **duo mille duo decem sex** |
| 250,000 | **duo centum quinque decem mille** |
| 1,000,000 | **milio** |

**Duo decem hostis detectum.**

**Quantum hostis detectum?**

**Quattuor decem septem hostis detectum.**  
Forty-seven enemies detected.

# XLII. GRAMMAR CONVENTIONS

System Latin has one verb paradigm and one status grammar. The same ending always means the same thing, so any form can be derived from a verb's command.

### The verb engine

Take the stem (the command without its final **-a**) and add the ending.

| Form | Ending | Example (stem *scan-*) | Use |
|---|---|---|---|
| Command | **-a** | **Scana.** | Order to one or many programs |
| I (self-report) | **-o** | **Scano.** | "I am doing this" |
| You | **-as** | **Scanas.** | "You are doing this" |
| It | **-at** | **Scanat.** | "It is doing this" (**Hostis appropinquat.**) |
| We | **-amus** | **Scanamus.** | "We are doing this" |
| You (all) | **-atis** | **Scanatis.** | "You are all doing this" |
| They | **-ant** | **Scanant.** | "They are doing this" (**Hostis appropinquant.**) |
| Passive | **-atur / -antur** | **Scanatur. / Scanantur.** | "It is / they are being done" (**Hostis possibilum sentatur.**) |
| Infinitive | **-are** | **Scanare.** | "To do this" (**termino / terminare**) |
| Ongoing (-ing) | **-ans** | **Scanans.** | "Doing this," invariant (**Hostis appropinquans.**) |
| Past (-ed) | **-av-** + person | **Scanavo / Scanavat / Scanavant.** | "Did this" (**Hostis evadavat.**) |
| Future | **-abs-** + person | **Scanabso / Scanabsat / Scanabsant.** | "Will do this" (**Hostis evadabsat.**) |
| Status | **-atum** | **Scanatum.** | "Done," a result state (**Hostis deletatum.**) |
| Action noun | **-atio** | **Scanatio.** | The act or result (**Reparatio**) |
| Agent noun | **-ator** | **Scanator.** | The doer (**Defendator**) |
| Required action | **-andum** | **Scanandum.** | "To be done" (**Activandum.**) |

### Persons and pronouns

The verb ending already shows the person, so pronouns are optional. Use them for emphasis, contrast, or as objects and possessors.

| Pronoun | Meaning | Verb ending |
|---|---|---|
| **Ego** | I | **-o** |
| **Tu** | you | **-as** |
| **Id** | it | **-at** |
| **Nos** | we | **-amus** |
| **Vos** | you (all) | **-atis** |
| **Ea** | they | **-ant** |

- Pronouns are caseless like nouns: **Zeto tu** means "I search for you," and **Telos nos** means "our objective" (head-first, like any noun).
- The command **-a** needs no pronoun and works for one program or many.
- **Nos** and **Ea** suit swarm or collective voices.
- The **-ct rule** affects only the status, noun, and agent forms; person endings stay regular (**Detectas, Detectamus, Detectant**).

**Examples**

**Hostis detectum. Defendamus.**  
Enemy detected. We defend.

**Tu scanas. Ego defendo.**  
You scan. I defend.

**Hostis appropinquant.**  
Enemies approaching.

**Ea retrahant. Nos progredamus.**  
They withdraw. We proceed.

### Demonstratives

| Word | Meaning |
|---|---|
| **Hic** | This (near the sender, or the most recently named) |
| **Ille** | That (far from the sender, or named earlier) |
| **Idem** | The same |
| **Alius** | Other / another |

- Demonstratives come before the noun and never change: **hic volator**, **ille volator autonomum**.
- They can stand alone as a pronoun: **Elimina ille.**
- With a quantity word, the demonstrative comes first: **hic tria hostis** (these three enemies).
- A demonstrative can also come before a dependent noun: **forma ille volator autonomum** (the shape of that drone).
- To point at one item among several of the same kind, add its code after the noun: **volator codex duo quattuor septem** (the flyer with code 247).

### Tense and aspect

| Meaning | Form | Example |
|---|---|---|
| Ongoing (-ing) | stem + **-ans** | **Hostis appropinquans.** (Enemy approaching.) |
| Present statement | stem + person ending | **Hostis appropinquat.** (Enemy approaches.) |
| Result state (done) | stem + **-atum** | **Hostis evadatum.** (Enemy escaped: it is in that state now.) |
| Past event (-ed) | stem + **-av-** + person ending | **Hostis evadavat.** (Enemy escaped: it happened.) |
| Future | stem + **-abs-** + person ending | **Hostis evadabsat.** (Enemy will escape.) |

- **-ans** never changes for person or number, so it works as a modifier: **Hostis scanans** (scanning enemy).
- **-av-** goes between the stem and the person ending: **Scanavo, Scanavas, Scanavat, Scanavamus, Scanavatis, Scanavant.** It works the same for every verb, including -ct verbs (**Detectavat**).
- **-abs-** works the same way: **Scanabso, Scanabsas, Scanabsat, Scanabsamus, Scanabsatis, Scanabsant.** The future passive is **-absatur / -absantur** (**Scanabsatur**). The past passive is the status form **-atum**.
- **Past and future are visibly distinct** (**Scanavat** and **Scanabsat**), so the tenses are hard to confuse in text.
- **-atum** describes the result and **-av-** reports the event, so logs can use either: **Ego scanavo. Hostis scanatum.** (I scanned. Enemy scanned.)
- The action noun **-atio** is the "-ing" noun: **Scanatio** means the scan or scanning.

**Stems.** Stems that end in **-i** keep it (**Redia, Exia, Aperia**). Monosyllabic **Sta** is already regular (stem *st-*).

**The -ct rule.** A stem that ends in **-ct** drops the *-at-* in the status, action noun, and agent noun. This keeps the most common status lines short: **Detecta / Detecto / detectum / detectio / detector**, and **Connecta / connectum / connectio**. It applies to **detect-, connect-, reconnect-, deconnect-, exspect-, restrict-,** and **suspect-**. Present, passive, and infinitive forms stay regular (**Detectat**).

**No classical verb forms.** Classical irregular commands, participles, and perfect tenses are not used; only their stems survive. **Progredere** is **Progreda**, **Acceptum** is **Accipatum**, and "escaped" is **evadatum**, not *evasit*.

### Nouns are caseless

Every noun has one form, the dictionary form. No case, gender, or number endings appear on nouns.

- **Relationships** use a preposition (**Ad locus, Ab locus, Ex copia, In initializatio**) or head-first juxtaposition (**Area patrōlium** = patrol area, **Copia securitas** = backup).
- **Who does what** is set by word order (see below), not by endings.
- **Plurals:** the noun does not change. The verb takes **-ant** (**Hostis appropinquant**), and quantity words supply the number (**multum, omnia, duo, tria**). Status forms never change (**Multum hostis detectum.**).
- **Data** and **Diagnostica** are mass nouns and keep their dictionary form.

### Species versus role

**Usor** names a role in the system: the human on the other end of the interface, the one with elevated priority and authority (see Section XLIX). **Homo sapiens** names a species, unrelated to role or system access. Both refer to the same people in this game, since only player characters are human, but a program uses one or the other depending on what it is actually detecting.

A program reading network traffic, permissions, and message envelopes sees **usor**. A program reading a body, a heat signature, or a behavioral pattern it cannot classify as code sees **homo sapiens** — it has identified a species, not yet a role. **Homo sapiens** is quoted scientific Latin, the real taxonomic binomial, and it is deliberately left outside the regularization engine: a species name is not System Latin's to systemize, any more than it is English's. It parses as an ordinary two-noun compound (**Homo**, head; **sapiens**, dependent), the same construction as **volator autonomum**, with no new grammar required.

**Tu non esat agent. Tu esat homo sapiens.** ("You are not a program. You are Homo sapiens.")

### Copula and identity

Most predication needs no linking verb: a status line puts the predicate directly after its subject (**Hostis activum.**, "the enemy is active"). That covers state.

**Esa** ("be") is a regular verb, for identity: saying that one thing *is* another, not merely how it currently is. It follows the standard paradigm like any other verb (**Eso, Esas, Esat, Esamus, Esatis, Esant**; past **Esavat**; future **Esabsat**; status **Esatum**; noun **Esatio**).

- **Identity:** **Hostis esat vehiculum autonomum.** ("The enemy is an autonomous vehicle.")
- **Self-identity:** **Eso usor.** ("I am the User.") The pronoun is optional, since the ending already carries "I": compare the bare juxtaposition **Telos tu** ("your objective"), which stays possessive, not identity.
- **State still needs no copula, and cannot take one:** **Esa** takes a noun as its predicate (identity), not an adjective or status word. **Hostis activum.** is the only valid form; **Hostis esat activum.** is not a System Latin sentence.
- **Latin's irregular copula (sum, es, est...) and Greek's (eimi, ei, esti...) are both suppletive and are not used.** **Esa** is the regularized, paradigm-following replacement for both, in keeping with the rest of the verb system.

### Alarm

**Sirena** is a regular verb, "sound the alarm," a Hellenistic loan from Greek **σειρήν** (seirēn) — the same root as the English word "siren." Rome had watchmen and bells, but not the specific concept of an automated warning signal, so this is a genuine gap-fill in the same category as the article (**to/ta/ti**), not a coinage from Latin material.

The paradigm gives every other form for free: **Sireno** ("I sound the alarm"), **Sirenat** ("it sounds the alarm"), **Sirenatum** ("alarm triggered," a status), **Sirenatio** ("the alarm," the noun for the event itself). Like other verbs, **Sirena** has no adverb of its own; the derivation rule in XLII applies only to adjectives.

**Sirenatio falsum.** ("False alarm.") is now the standard phrasing, replacing the earlier workaround **Minatio falsum**, which reused "threat" rather than naming the alarm itself.

### Lexical sourcing

System Latin's vocabulary is primarily Latin. Where Latin has no word for a concept Latin itself never needed, or where a Latin coinage would be awkward, the language borrows from Greek or other Hellenistic sources instead of inventing an arbitrary form. The clearest case is the article.

**To** is the definite article, "the." It is invariant, like the demonstratives, and always precedes a noun (directly, or before a demonstrative or quantity word): **to hostis**, **to ille volator autonomum**, **to tria hostis**. It has no plural or gendered form, and it cannot stand alone. Latin itself has no article, so this is not a regularization of a classical word; it is a deliberate gap-filling loan. **Zeto**, from Greek, was the language's first such loan.

**Three source layers, used in order:**

1. **Latin** is the primary and default source for all vocabulary, run through the regular paradigm.
2. **Greek** fills a genuine classical-era gap: a grammatical category or a concept Rome itself had no word for, where a Greek word already exists and is recognizable (often because it survives as an English loanword). **To/ta/ti** (the article) and **Sirena** ("alarm," from **σειρήν**, the root of "siren") are the two cases so far.
3. **Interlingua** fills a modern gap: a technological or international concept that has no classical Latin or Greek equivalent at all, where Interlingua (an existing naturalistic auxiliary language built from the common vocabulary of English, French, Italian, Spanish, and Portuguese) already has a form that is widely recognizable across languages. This tier hasn't been used yet, but it is the intended source for words like **robot**, **computer-network** terminology, or other concepts that postdate antiquity entirely and that Interlingua's own dictionary already covers in a form Rome and Athens never could.

System Latin has three articles, one word per article per Greek's own three-way split of *the* by number, minus gender (Greek's own genderless neuter forms: **to** ("the," from Greek **τό**), **ta** ("the," plural, from Greek **τα**), and an indefinite **ti** ("a / an," from Greek **τις**, "someone / something," since Greek itself has no indefinite article either).

- **To** is the default, and covers a general or singular "the": **to hostis**.
- **Ta** marks a plural "the," matching a plural verb or **multum**: **ta hostis appropinquant** ("the enemies approach"). It is a convention, not an enforced agreement; the grammar does not check that a plural article co-occurs with a plural verb.
- **Ti** marks "a / an": **ti volator autonomum suspectum** ("a suspected autonomous drone").
- Only one article may appear in a noun phrase; they never stack (**to ta hostis** is invalid), though an article and a demonstrative can combine (**to ille volator**).

**To** is optional. Most status and command lines read naturally without it (**Hostis detectum.**), and it is best reserved for lines where definiteness matters, such as picking out one specific thing already in view (**Elimina to volator.**).

### Adjective regularization (systemization pass 2)

Earlier passes regularized verbs, nouns, agreement, and articles, but left adjectives with four different endings inherited from Latin's own declension classes (**-um, -ile, -ale**, and a few irregular comparatives). Every adjective is now **-um**, with no exception: **possibile → possibilum**, **stabile → stabilum**, **normale → normalum**, **forte → fortum**, **vetus → vetusum**, **prius → priusum**. The only word that keeps a different shape is **minus**, which is not a descriptive adjective here but a comparison operator (see the Comparison words in Section XLV), alongside **aequale** and **maius**.

### Derived adverbs

Manner adverbs are no longer a closed, irregular list. Any adjective can form its adverb by dropping the final **-um** and adding **-iter**: **fortum → fortiter** ("strongly"), **celerum → celeriter** ("quickly"), **tardum → tarditer** ("slowly"), **activum → activiter** ("actively"). This mirrors the verb paradigm: the adverb is derived from the word, not looked up.

A small set of temporal and frequency words has no adjective to derive from and stays as its own closed class, the same status as the rule words (**si, dum**) or question words (**ubi, quando**): **nunc, iam, semper, numquam, statim, postea, iterum**. These describe *when*, not *how*, and English keeps the same split ("quickly" is derived from "quick"; "now" and "never" are not derived from anything).

**Retired:** **celeriter** and **tarde** as separate lexical entries (they are now derived, from **celerum** and **tardum**), and **cito**, which duplicated **celeriter**.

### Word order

The verb always comes before its object. A stated subject comes before the verb.

| Rule | Example |
|---|---|
| Commands and infinitives are verb-first. | **Elimina minatio.** (Eliminate the threat.) |
| A stated subject comes before the verb. | **Hostis scanat nodus.** (The enemy scans the node.) |
| Self-reports and commands need no subject. | **Zeto hostis.** (I search for the enemy.) |
| Status lines put the subject first, then the status. | **Hostis detectum.** (Enemy detected.) |
| Prepositional phrases follow the verb. | **Progredo ad locus.** (I proceed to the location.) |
| Modifiers and possessors follow their noun; numbers, quantity words, and demonstratives come before it. | **Zona periculosum.** / **Telos tu.** / **Tria hostis.** / **Ille volator.** |
| **Non** comes right before what it negates. | **Non redia.** (Do not return.) / **Non detectum.** |
| Duty or purpose: noun, colon, infinitive. | **Telos tu: eliminare minatio.** (Your mission is to eliminate the threat.) |
| Question words come first, whatever role they fill. | **Ubi hostis?** (See XLVI.) |

**Full example**

**Telos tu: eliminare minatio. Non redia donec id terminatum.**  
Your mission is to eliminate the threat. Do not return until it is terminated.

### Other conventions

1. **Status lines use neuter -um / -e.** A noun followed by a status form takes the neuter form regardless of the noun's gender or number.
   - **Hostis detectum.** / **Connectio perdatum.** / **Reparatio completum.**
   - Players learn that **-um** means "this is a status."
   - Ongoing forms (**-ans**) are invariant and stay as they are (**urgans, imminans**).
2. **Plurals:** the noun and the status form do not change. Verbs take **-ant / -antur**, and quantity words supply the number: **Multum hostis detectum.** / **Omnia processus activum.**
3. **Command versus self-report:**

| Command (to another program) | Self-report (I am doing this) |
|---|---|
| **Scana.** | **Scano.** |
| **Detecta.** | **Detecto.** |
| **Zeta.** | **Zeto.** |
| **Progreda.** | **Progredo.** |
| **Persequa.** | **Persequo.** |
| **Retraha.** | **Retraho.** |

4. **Every modifier is neuter.** Adjectives, determiners, numbers, and ordinals always take the neuter form, whether they report a state or name a kind of thing: **Zona periculosum.**, **Area restrictum.**, **Prioritas altum.**, **Nullum motus.**, **Unum, duo, tria.**
5. **Negation uses Nullum:** **Nullum anomalia detectum.** / **Nullum signum.**
6. **No untranslated English in messages.** English-cognate nouns (**Error, Sensor, Console**) are fine. Whole English words like *online* or *optional* are replaced (**Systema connectum**, **Optionale**).

# XLV. LOGIC AND CONTROL FLOW

Control words are uninflected particles, so they never take endings. Every condition is a status line (**Hostis detectum**), and every action is a command (**Defenda**). A program can read a rule aloud in one pass.

| Word | Meaning | Context |
|---|---|---|
| **Si** | If | Check a condition once. |
| **Tunc** | Then | Optional; marks the action after a condition. |
| **Aliter** | Else | The branch taken when the condition fails. |
| **Aliter si** | Else if | The next condition to check. |
| **Nisi** | Unless | Shorthand for "if not." |
| **Quando** | When | Trigger on an event, every time it happens. |
| **Finis** | End (of block) | Optional; closes a rule or loop. |

| Command | Meaning | Status |
|---|---|---|

### Which word owns which context

- **Si** checks once. **Quando** waits for an event. **Dum** keeps checking. That gives three distinct ways to say "if something is true."
- **Dum** loops while the condition is true, and **Donec** loops until it becomes true.
- **Exia** leaves a loop; **Continua** skips one round; **Redia** returns.

### Examples

**Si hostis detectum, tunc defenda.**

**Si via obstruatum, retraha. Aliter, progreda.**

**Si energia insufficians et hostis detectum, retraha.**

# XLVI. QUESTIONS

Questions use uninflected question words, and the question word always comes first, whichever role it fills. The rest of the clause keeps normal word order. Written questions end with **?**.

### Question words

| Word | Meaning | Answered with |
|---|---|---|
| **Utrum** | Whether (yes/no question) | **Affirmatum.** / **Negativum.** |
| **Quis** | Who | A noun or pronoun |
| **Quid** | What | A noun or statement |
| **Quale** | Which / what kind | A noun or modifier |
| **Ubi** | Where | A location or **prope / longe** |
| **Quando** | When | **Nunc, ante, post**, or a status |
| **Cur** | Why | A reason: a status or **Causa** |
| **Quomodo** | How | A command or method |
| **Quantum** | How much / how many | A number or **multum, omnia** |

### Rules

1. **Question word first.** Even when it is the object, it leads: **Quid scanas?** (What do you scan?)
2. **Yes/no questions** start with **Utrum** and then a normal clause: **Utrum hostis detectum?** The answer is **Affirmatum.** or **Negativum.**
3. **Direction** uses the same prepositions as any noun: **Ad ubi** (to where), **Ab ubi** (from where).
4. **Embedded questions** use the same words without **?**: **Verifica utrum hostis detectum.**
5. **Quando** also means "when" in a rule (Section XLV). A **?** or a missing action marks it as a question: **Quando hostis detectum?** versus **Quando hostis detectum, defenda.**
6. **No copula.** "Where is the enemy?" is just **Ubi hostis?**

### Examples

**Utrum hostis detectum?**  
Is the enemy detected?

**Affirmatum.**  
Yes.

**Ubi hostis?**  
Where is the enemy?

**Hostis prope.**  
The enemy is near.

**Quis scanat nodus?**  
Who scans the node?

**Nos scanamus nodus.**  
We scan the node.

**Quid scanas?**  
What do you scan?

**Scano nodus.**  
I scan the node.

**Cur retrahas?**  
Why do you withdraw?

**Periculum imminat.**  
Danger is imminent.

**Quantum hostis detectum?**  
How many enemies detected?

**Tria hostis detectum.**  
Three enemies detected.

**Quomodo reconnectare?**  
How to reconnect?

**Resetta connectio.**  
Reset the connection.

**Ad ubi progredamus?**

# XLVII. MACHINE SYNTAX

This section fixes every ambiguity a parser could hit. The companion files are **sl_grammar.ebnf** (formal grammar), **sl_lexicon.json** (words with part of speech), **sl_parser.py** (reference parser and validator), and **sl_tests.txt** (test corpus).

### Canonical form

- Lowercase ASCII letters only. Macrons are stripped (**patrolium**), and capitalization carries no meaning.
- Punctuation is limited to **.** (statement end), **?** (question end), **,** (separates a condition from its action, or one action from the next), and **:** (purpose form).
- Whitespace separates tokens. Every message ends with **.** or **?**.

### Sentence types

| Type | Shape | Example |
|---|---|---|
| Command | verb, object, modifiers | **Scana nodus.** |
| Finite clause | [subject] verb [object] | **Hostis scanat nodus.** |
| Status | subject, predicate | **Hostis detectum.** |
| Purpose | noun **:** infinitive clause | **Telos tu: eliminare minatio.** |
| Rule | **si / nisi / quando / dum / donec** condition **,** actions | **Si hostis detectum, defenda.** |
| Else chain | **aliter,** actions / **aliter si** condition **,** actions | **Aliter, progreda.** |
| Loop over items | **quisque** noun **,** actions | **Quisque nodus, scana.** |
| Question | question word first, **?** at the end | **Ubi hostis?** |
| Answer | **affirmatum / negativum** or a statement | **Negativum.** |

### Resolved ambiguities

1. **Noun sequences.** A noun phrase is a head noun plus at most one dependent noun or pronoun (**area patrolium**, **telos tu**). Three adjacent nouns are an error. A verb takes one object, and any other argument needs a preposition.
2. **Adjectives.** An adjective after a noun modifies it, except when it is the last word of the clause, where it is the predicate: **Hostis activum.** means the enemy is active. Participles (**-um, -ans**) are predicates only.
3. **Negation.** **Non** comes directly before the predicate it negates (**Hostis non detectum.**, **Non redia.**). Anywhere else is an error.
4. **Conditionals.** One rule per sentence, with branches separated by commas. Nesting is not allowed. **Aliter** and **aliter si** must directly follow a **si**, **nisi**, or **aliter si** sentence. **Finis.** closes a chain.
5. **Quando.** With **?** it is a question, and with a comma it is a trigger.
6. **Infinitive complement.** A verb may take an infinitive: **Tenta connectare.**
7. **Numbers** have one valid spelling per value (**unum** never comes before a place word), and **negatum** marks a negative number.
8. **Renamed to remove clashes:** the preposition **intra** is now **intus** (the command **Intra** is unchanged), the sign **minus** for negatives became **negatum**, and **signum** now means only "signal."
9. **Demonstratives** (**hic, ille, idem, alius**) come before the noun or before a dependent noun, and can stand alone. A dependent can also be a code: **volator codex duo quattuor septem.**
10a. **Esa** ("be") is a regular verb reserved for identity statements; state uses a bare status line with no copula (see XLII).
11a. Every adjective is invariant **-um**, and any adjective can form a manner adverb by replacing **-um** with **-iter** (see XLII).
11b. **Sirena** ("sound the alarm," Greek) is a regular verb; its noun form **Sirenatio** names the alarm event itself (see XLII).
10. **To, Ta, Ti** (Greek articles) are invariant, at most one per noun phrase, and come before everything else, including a demonstrative: **to ille volator.**

### Error codes

| Code | Meaning |
|---|---|
| E_CHARSET | Character outside the canonical set |
| E_UNKNOWN | Word not in the lexicon or paradigm |
| E_TERMINATOR | Message does not end in . or ? |
| E_QMARK | Question word and **?** do not match |
| E_SYNTAX | Structure does not match any sentence type |
| E_NOUNS | Too many adjacent nouns |
| E_VALENCY | Object given to an intransitive verb |
| E_NEG | **Non** not before a predicate |
| E_NESTED | Rule inside a rule branch |
| E_ELSE | **Aliter** without a preceding rule |
| E_NUMBER | Malformed number |

# XLVIII. MESSAGE ENVELOPE

A message between programs starts with an envelope sentence. The envelope names the sender and receiver, and it can carry a priority, a reply link, and a timestamp. Every message has a body of ordinary sentences after it.

**Nuntius codex** *id* **:** **ab** *sender* **, ad** *receiver* [**, prioritas** *level*] [**, responsum codex** *id*] [**, tempus** *number*] **.**

### Fields

| Field | Meaning | Required | Form |
|---|---|---|---|
| **Nuntius codex** | Message ID | Yes | A digit string: **nuntius codex unum duo tria** |
| **ab** | Sender | Yes | Must carry a code: **ab agent codex quattuor** |
| **ad** | Receiver | Yes | A code, or **omnia** for a broadcast: **ad agent codex quinque**, **ad omnia volator**, **ad omnia** |
| **prioritas** | Priority | No | **minimum, humile, normale, altum, maximum** (**normale** if omitted) |
| **responsum codex** | Reply to message | No | The ID of the message being answered |
| **tempus** | Timestamp | No | A number, such as a game tick |

### Rules

1. The envelope is the first sentence and ends with **.**
2. Each field appears at most once, and fields are separated by commas.
3. The body follows as ordinary sentences.
4. In strict mode (the game runtime), a message without an envelope is rejected. Lenient mode accepts bare sentences for testing.

### Examples

**Nuntius codex unum duo tria: ab agent codex quattuor, ad agent codex quinque, prioritas altum. Suspecto volator autonomum codex duo quattuor septem. Elimina id.**  
Message 123 from agent 4 to agent 5, high priority: I suspect the autonomous drone with code 247. Eliminate it.

**Nuntius codex unum duo quattuor: ab agent codex quinque, ad agent codex quattuor, responsum codex unum duo tria. Affirmatum. Eliminavo volator codex duo quattuor septem.**  
Message 124 from agent 5 to agent 4, replying to message 123: Yes. I eliminated the drone with code 247.

**Nuntius codex septem: ab agent codex unum, ad omnia volator, prioritas maximum. Redia.**  
Message 7 from agent 1 to all drones, maximum priority: Return.

### Error codes

| Code | Meaning |
|---|---|
| E_ENVELOPE | Missing, duplicated, unknown, or malformed envelope field |
| E_ADDRESS | Sender or receiver without a code (or **omnia** for a receiver) |
| E_PRIORITY | Priority is not one of the five levels |

# XLIX. HOST AUTHORITY, FRAMES, AND PACKS (v1.2)

This section covers the game's peer-to-peer layer. It is not part of the language itself, but the language is designed around it: canonical text makes every message signable, and strict validation makes every peer a safe checker.

### Host per world

- Each world has one **host** peer. The host is the only peer that assigns sender codes, message IDs, and timestamps, and that decides priority.
- A client sends a **request frame** containing only the body text. The host verifies the client's signature and role, writes the envelope, signs the result, and broadcasts a **world frame**.
- Every peer verifies the host's signature, parses the text, and drops anything invalid.
- The host is authoritative for game state. The language only carries intent, so a drone is destroyed when the host says so.
- Clients keep their own signed request frames as proof of what they sent. Host migration and disputes about a forging host are left for a later version.

### Roles and priority ceilings

The host clamps a message's priority to the sender's ceiling. A message that asks for more is delivered at the ceiling, not rejected.

| Role | Who | Ceiling |
|---|---|---|
| **administrator** | The host and world admins | **maximum** |
| **usor** | A player | **altum** |
| **agent** | A friendly program | **altum** |
| **adversarius** | A hostile program | **normale** |
| Unregistered | A peer that has not joined | **humile** |

Each peer gets one code when it joins (**ab usor codex quattuor**). Role grants are tokens signed by the host, with an expiry.

### Frames

Frames belong to the transport layer, not the language.

| Field | Request frame | World frame |
|---|---|---|
| Spec version and pack hashes | Yes | Yes |
| Canonical text | Body only | Envelope and body |
| Sender key and signature | Yes | Yes (proof of authorship) |
| Host key and signature | No | Yes |
| Sequence number | No | Yes, strictly increasing per world |

Signatures cover the UTF-8 bytes of the canonical text. Peers reject a world frame whose sequence number does not increase, or whose timestamp is outside the host's window.

### Handshake

1. **HELLO** (peer to host): spec version, pack hashes, public key.
2. **WELCOME** (host to peer): world ID, assigned code, role, required pack hashes, host key.
3. A different spec major version is refused. A missing pack is fetched by hash and verified before use.

### Limits

| Limit | Default |
|---|---|
| Bytes per message | 1,024 |
| Tokens per message | 200 |
| Sentences per message | 16 |
| Digits in a code | 16 |
| Rate | 10 messages per 10 seconds per peer (host setting) |
| Strikes | 3 invalid messages, then mute (host setting) |

Going over a message limit is **E_LIMIT**.

### Canonical text

- Lowercase ASCII, single spaces between words, no space before punctuation, one space after it, no trailing space.
- Canonicalizing twice gives the same text, and the parse tree is unchanged.
- Example: **RESUMA   patrōlium .** becomes **resuma patrolium.**

### Vocabulary packs

A pack is a JSON manifest that adds vocabulary and phrases to a world without touching the core.

| Field | Meaning |
|---|---|
| **pack, version, spec** | A lowercase name, semantic version, and the spec version it targets |
| **license, author** | Required |
| **verbs** | Stems with a gloss and **trans** or **intrans** (regular paradigm only) |
| **words** | Nouns, adjectives, and adverbs, each with a gloss |
| **phrases** | Templates with tags and a weight of 1 to 10 |

- A pack cannot add grammar words (prepositions, pronouns, question words, numbers, and so on), and it cannot redefine a core word or share a word with another pack.
- Every word needs an English gloss, so players and moderators can see what a pack says.
- Templates use the slots **{noun}**, **{adj}**, **{number}**, and **{code}**. The linter fills every slot with samples and rejects a template that ever fails to parse.
- A pack's identity is the SHA-256 hash of its canonical JSON, and the author signs that hash.
- The linter is **sl_pack.py**, and limits are 50 verbs, 500 words, and 200 phrases per pack.

| Code | Meaning |
|---|---|
| P_SCHEMA, P_NAME | Missing field or bad name |
| P_SPEC | Wrong spec major version |
| P_COLLISION | Word or verb form already exists |
| P_POS | Part of speech not allowed in a pack |
| P_GLOSS | Missing gloss |
| P_TEMPLATE | A phrase template fails to parse |
| P_LIMIT | Too many entries |
